Transactions fail. The difference between a beginner and a competent operator is knowing why they fail and how to fix them.                                    

In this module you intentionally break a transaction, read the error, then fix and resubmit it. Everything here is safe — failed transactions on the testnet   
cost nothing.

Press Enter to continue...Submit a failing transaction                                                                                                                                   

We are going to submit a transaction that we know will fail: a payment of more XRP than your wallet holds. This is safe — on the XRPL Testnet a failed         
transaction costs only test XRP (a tec result still charges its fee) and harms nothing.                                                                        

Common failure modes on XRPL:                                                                                                                                  

 • tecUNFUNDED_PAYMENT — not enough XRP                                                                                                                        
 • tecNO_DST — destination account doesn't exist                                                                                                               
 • tefBAD_AUTH — wrong signing key                                                                                                                             
 • tecPATH_DRY — no liquidity path (for issued currencies)

  Result code: tecUNFUNDED_PAYMENT
  Error: Sender doesn't have enough XRP. Fund your wallet: xrpl-lab fund

Press Enter to continue...Read the error                                                                                                                                                 


Look at the result code above. Every XRPL result code has a prefix that tells you the category:                                                                

                                                                              
 Prefix  Meaning                                                              
 ──────────────────────────────────────────────────────────────────────────── 
 tes     Success                                                              
 tec     Claimed — tx applied but failed (on the ledger; the fee was charged) 
 tef     Failed — tx not applied                                              
 tel     Local — client-side rejection                                        
 tem     Malformed — invalid tx format                                        
 ter     Retry — might work later                                             
                                                                              

The result code tells you what happened. The category tells you how bad.                                                                                       

Press Enter to continue...Fix and resubmit                                                                                                                                               

Now let's submit the same payment correctly. The fix depends on what failed:                                                                                   

 • Underfunded? Fund the wallet or reduce the amount.                                                                                                          
 • Bad destination? Use a valid address.                                                                                                                       
 • Auth error? Check the signing wallet.
